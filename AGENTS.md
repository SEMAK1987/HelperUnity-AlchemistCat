# Правила проекта «Алхимический Кот» (Alchemist Cat)

## 1. Стиль документирования и комментариев
- **Боковые комментарии на русском языке (`//`)**: при создании новых скриптов или изменении существующего кода всегда добавлять понятные построчные комментарии сбоку от кода.
- **Обязательные блоки для описания**:
  - Все публичные и приватные переменные, структуры, поля сериализации и ссылки на UI.
  - Методы жизненного цикла Unity: `Awake()`, `Start()`, `Update()`, `OnEnable()`, `OnDisable()`.
  - Места внесения изменений: четко пояснять, за что отвечает добавленная/измененная логика, что включается и выключается.
- Избегать громоздких блоков комментариев сверху, отдавать предпочтение удобным для чтения при прокрутке боковым подсказкам.

## 2. Работа с UI и Unity Inspector
- Не перезаписывать в коде параметры верстки UI (выравнивание текста, отступы), если они настраиваются через инспектор Unity.
- Соблюдать правила работы с компонентами `TextMeshProUGUI` и стандартными компонентами Unity UI.
- Всегда реализовывать гибкую поддержку обоих типов компонентов (`TextMeshProUGUI` / `Text`, `Image (Fill)` / `Slider`), чтобы исключить ошибки перетаскивания (drag-and-drop) в инспекторе Unity.

## 3. Синхронизация и актуальность кодовой базы в Code
- **Обязательное обновление скриптов**: при любых исправлениях, рефакторинге или запросах пользователя ВСЕ соответствующие файлы скриптов (`.cs`) во вкладке **Code** (проводник проекта) должны быть немедленно обновлены до актуального рабочего состояния.
- **Никаких устаревших версий в файлах**: гарантировать, что код в файлах точно совпадает с решением, прошел компиляцию и не содержит дубликатов методов или отсутствующих ссылок.
- **Ведение базы знаний и документации**: регулярно актуализировать `knowledge_base.json`, `metadata.json`, `version.json`, `DEVELOPMENT_LOG.md`, `PROJECT_MASTER_BLUEPRINT.md` и `AI_ASSISTANT_RECOVERY_GUIDE.md`.
